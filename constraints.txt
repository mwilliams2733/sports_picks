# Pinned dependency set for reproducible installs.
#
# Why this file exists
# --------------------
# pyproject.toml specifies floors (">=") only, so `pip install -e .` resolves
# whatever is newest on the day it runs. Dockerfile and CI both do exactly
# that, which meant two identical builds a month apart could ship different
# major versions with no commit in between. That is how the local venv came to
# sit on starlette 0.52.1 while CI and production resolved starlette 1.6.0.
#
# This file pins the resolved set so an upgrade is a reviewable diff rather
# than a side effect of the calendar.
#
# Consumed by
# -----------
#   Dockerfile          pip install -e . -c constraints.txt
#   .github/workflows/  pip install -e '.[dev]' -c constraints.txt
#
# A constraint only caps the version of a package that something else already
# pulls in -- it never causes an install. Entries that apply to one platform
# only (colorama) are therefore inert elsewhere.
#
# Regenerating
# ------------
#   pip install -e ".[dev]" --upgrade --upgrade-strategy eager
#   pip freeze | grep -v "^-e " > constraints.txt   (then restore this header)
#   pytest backend/tests -q
# Push and let the 3.12/3.14 matrix confirm the set works on both runtimes
# before trusting it.
#
# Generated 2026-09-17 from Python 3.14 on Windows; validated by CI on 3.12
# and 3.14 (linux).
