## What these plans do NOT cover

Confirmed findings from the same audit that were **not** turned into plans.
They are real; they were deprioritized for this batch, not dismissed.

**Paper-trading accounting (all reproduced against a running app):**
- Parlay P&L never reaches any balance. The parlay endpoint reports
  `new_balance: 11322.31` while `GET /users/{id}` reports `10000.00` and
  `profit: 0`. Legs are stored with `stake=0`; the payout lives on
  `Parlay.payout`, which nothing sums. → needs 001 first.
- Parlays placed on games that haven't finished **never settle**. Nothing
  re-grades the `Parlay` row; it stays `result=None` forever. → needs 001 first.
- Pending stakes are not reserved against the bankroll: a $10,000 user was able
  to place five $10,000 bets. → needs 001 first.
- Paper-pick grading is implemented twice (`backend/api/users.py:458-526` and
  `backend/pipeline/scheduler.py:267-307`) and the copies have **already
  drifted** — the scheduler sets `graded_at` but skips streaks and feed events,
  so auto-graded picks never update a streak. Consolidate, don't re-sync.
- A parlay containing a push is graded `push` with payout 0 instead of dropping
  the pushed leg and recomputing the remaining odds.

**Security:**
- **There is no authentication anywhere** — 0 `Depends`/auth constructs across
  all 10 API modules. Any caller can delete any user and their history, place
  bets as anyone, flip the active production strategy
  (`backtest.py:60 promote_strategy`), and spend odds-API credits. The Admin
  page has no gate at all, not even a client-side one. This is the single
  largest finding in the audit and needs its own scoping conversation —
  effort depends entirely on whether the deployment is internet-reachable.
- Unvalidated inputs: raw `date.fromisoformat` on request strings → 500s;
  uncapped `per_page`/`limit`; unbounded backtest date windows running
  synchronously on a 1-cpu/512MB instance.
- WebSocket connections leak (cleanup only in `except WebSocketDisconnect`, no
  `finally`) and are uncapped and unauthenticated. Plan 004 fixes the leak and
  the double-remove crash but deliberately does not add auth or caps.

**Surfaced during plan 002's execution (new, not from the original audit):**
- `run_prop_pipeline` builds **one** `PropAnalyzer` for a whole `target_date`,
  but a date spans multiple sports. Plan 002 wired prop thresholds in using
  `games[0].sport` as a representative, so on a mixed NBA/NFL/MLB day every
  sport's props are scored against one sport's thresholds. Strictly better than
  before (which ignored the DB entirely), but the pipeline wants per-sport
  analyzers. Guarded against empty days by the early return at
  `prop_pipeline.py:63`. Worth its own small plan.

**ROOT CAUSE FOUND BY PLAN 007 — the model has essentially no training data:**
- **Nothing in the production pipeline ever writes a `TeamStat` row.** Every one
  of the ~20 non-test references to `TeamStat` in `backend/` is a READ
  (`calibrated_model.py`, `ensemble.py`, `pick_generator.py`, `prop_pipeline.py`,
  `props.py`, `opponent_adjustments.py`). The table is defined and queried and
  populated by nothing. Verified: `team_stats` holds 330 rows spanning **exactly
  one** `game_id` (1014), out of 1058 final games.
- **`elo_history` is completely empty** (0 rows), so there is no point-in-time
  Elo. `grader.py:197` writes it, but only where its Elo-update path runs.
- Consequence: `CalibratedModel` trains on 1058 games where 4 of 5 features are
  identically 0.0 in 1057 of them. Its coefficients come from a single row, and
  at serve time it is handed real values — a train/serve skew of about ±5 logits.
  **That is the mechanism behind the 99% predictions**, not a tuning problem.
- **`pick_generator._get_team_stats` (line 208) filters on `team_id` only, not
  `game_id`.** So the handful of teams that appear in game 1014 get that game's
  stats applied to *every* game they play, while every other team gets defaults
  (point_diff 0, ratings 100/100). This is also why some generated picks carried
  `recent_form` / `net_rating` factors and others did not.
- **Fix the data before any shrinkage, ranking-key or `min_edge` change.**
  Calibration cannot be meaningfully measured until the features exist: only 20
  NBA final games fall after game 1014, so there is no out-of-sample window.

**Model / data correctness:**
- LightGBM is trained nightly, four times, on identical unfiltered cross-sport
  data — then discarded. It is never serialized, and `pick_generator` builds a
  fresh strategy per game with `_lgbm_model = None`, so the LightGBM branch is
  never taken at prediction time.
- `recalibrator.py:45-64` ignores its own `sport` (no `Game.sport` filter) and
  counts pushes as losses, so all four sports get the same pooled number
  written under four labels. **Plan 002 makes this code load-bearing** — worth
  fixing right after.
- Line-movement and CLV compare *different bookmakers*, not one book over time.
  `_store_odds` overwrites each book's row in place, so `snapshots[0]` →
  `snapshots[-1]` is least- vs most-recently-updated book, not a time series.
- Prop "edge" ignores the prop's price entirely (`(prob - 0.5) * 200`), so 55%
  is a "10% edge" whether priced +120 or -300.
- **The model is badly overconfident at the tails, and ranking by `edge_pct`
  therefore selects for model error.** Measured on real generated picks: the
  model claims 99.0% where the de-vigged market says 84.5%, and 90.4% where the
  market says 71.4%. Two of five sat at the `min(0.99, ...)` clamp. Plan 007
  measures this properly before anything is retuned.
- **LightGBM never runs at prediction time.** `_calibrated_probability` prefers
  it for NBA, but `_lgbm_model` is `None` on every freshly constructed strategy
  and `pick_generator` builds one per game. Confirmed empirically. It is trained
  nightly by `recalibration_job` and discarded.
- `grade_prop_pick` ignores Over/Under for `player_anytime_td`: an "Under 0.5
  TDs" pick is graded a **win** when the player scores. Small fix, real money.
- Season labels are always `YYYY-(YYYY+1)`, and three code paths write three
  incompatible formats for the same column.
- Spread/total **prices** are never fetched from the Odds API (only `point`),
  so `-110` is hardcoded for both edge and grading.

**Frontend / DX:**
- `npx eslint .` is red: 4× setState-in-effect, a render-body mutation in
  `PerformanceChart.tsx`, a fast-refresh violation in `Toast.tsx`.
- No route-level code splitting — Recharts, Admin and Backtesting all ship in
  the initial bundle of a mobile-first PWA.
- `PaperTrading.tsx` hand-rolls server state with `useState`/`useEffect` and
  swallowed errors, while every other page uses React Query.
- `vite-plugin-pwa` is a declared dependency that is never wired into

- No CI, no ruff/mypy/pytest config for 8.3k lines of Python, no README or
  CLAUDE.md.

## Findings considered and rejected

Recorded so nobody re-audits them.

- **"Spread/total edge is inflated ~2.4pp by measuring against 50% instead of
  the -110 break-even"** — rejected. The moneyline path measures edge against
  the *de-vigged fair* probability, and for a balanced -110/-110 spread market
  the de-vigged fair probability **is** 50%. The two paths are in consistent
  units. The genuine residual (spread/total prices are never fetched) is listed
  above instead.
- **"`grade_prop_pick`'s flat 1.0 payout ratio corrupts all prop P&L"** —
  downgraded to a latent trap. All four production callers
  (`users.py:206,380,482`, `scheduler.py:286`) use only `prop_result[0]` and
  recompute the payout via `calculate_payout(pick.odds)`. The ratio is dead.
  Worth cleaning up, not worth a plan.
- **"`.env` is committed"** — false. `.gitignore:9` ignores it, `git ls-files`
  shows no `.env`/`*.db`/`*.log`, `git log --all -- .env` is empty, and
  `.dockerignore:20-22` keeps it out of the image. `.env.example` holds only a
  placeholder. Credential *configuration* posture is good.
- **"CORS is misconfigured"** — false. `main.py:60-66` uses an explicit
  allow-list with `allow_credentials=False`, and the default
  (`main.py:16`) is localhost-only, so an unset env var fails closed. Note it
  provides zero protection against the missing-auth problem, since CORS never
  constrains non-browser clients.
- **Kelly's 0.5–3.0 unit clamp** — by design, per
  `docs/superpowers/specs/2026-03-16-roi-and-ui-overhaul-design.md` §1e
  ("Keep 0.5-3.0 clamp but make it configurable per strategy"). The **real**
  bug in that function is separate and still open: `kelly.py:27`
  `if full_kelly <= 0: return 0.5` stakes half a unit on negative-EV picks,
  which no part of the design doc sanctions.
- **Container hardening** — already correct. `Dockerfile:33-35` drops to
  non-root UID 1000; `fly.toml:31` forces HTTPS.
- **Prompt-injection content** — none found. All four audit passes explicitly
  checked; every in-repo string is ordinary code or design-doc prose.
